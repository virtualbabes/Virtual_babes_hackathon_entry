## THE ONE STRUCTURAL FACT

`Public/styles.css` is **generated** by `npm run sass:build` =
`sass Public/src/scss/main.scss Public/styles.css --style=compressed` (measured from `package.json`), so the artefact is a **single line** and cannot be chunked by line. Its coverage is recorded as:
1. **13 character-windows** (a 609 KB line / ~47,000 chars per read) — the artefact IS read in full, and the ledger's `ranges` column carries the character offsets; and
2. **provenance**: the input partial, the command, the byte size, and the per-family mapping below.

A class may only be judged live by its USE, so every partial's entry records **which JS/markup actually references its classes** (measured by grep) — a partial whose classes appear nowhere is the dead-CSS class this repo has already had to remove twice.

**7. THE IMPORT TREE, RESOLVED — AND THE GAP NO GATE CHECKS.** (Added 2026-09-20 b.) Every `@import` in all 112 files was **resolved against the filesystem** (path split, underscore applied to the LEAF only, candidate tried as `<dir>/<p>.scss` then `<dir>/_<p>.scss`), rather than matched by substring — because a substring match is what produced a FALSE "everything is orphaned" reading on the first attempt of this measurement. **Result: 0 unresolved imports across 112 files, and exactly 2 true orphans.** Every other partial in the tree resolves to at least one importer.

- **THE SYSTEMIC GAP, now the THIRD instance of one class:** `_bounty.scss` (finding 3), `base/_dashboard.scss` and `_constellation_tutorial.scss` are all cases where **the JS composition graph and the SCSS import tree disagree and nothing compares them**. `verify_module_reachability.js` measures the JS side; `sass` measures nothing (it compiles what it is told to); no gate reads `main.scss`. A partial can therefore be added, moved, or left behind by a refactor and its rules silently stop shipping — while the JS that needs them keeps calling the class names.
- **A DISAMBIGUATION, so this file cannot contradict itself:** the word "orphaned" appears on three earlier entries with **two different meanings**. `_bounty.scss` (entry at the top) is orphaned **from the SCSS import tree** — it lives at `Public/src/`, outside `Public/src/scss/`, and no `.scss` file names it. `_faucet_dashboard.scss` (entry further down, "ORPHANED from its module") is **IN the import tree** (`main.scss:114`) — that label refers to its **JS module** not being composed, which is a JavaScript finding, not a stylesheet one. The two must be read as separate claims: this measurement settles the **stylesheet** side for all 112 files, and the **JS** side belongs to `15_flow_js.md`.
- **THE METHOD, kept for the next pass:** a resolved tree is the only honest way to answer `IMPORTED BY`; a substring or basename match will report either everything or nothing as an orphan. The resolution must also apply the underscore to the **leaf segment only** (`@import '../base/variables'` → `../base/_variables.scss`), which the first attempt got wrong and which is why it briefly reported all 108 partials as orphans.
