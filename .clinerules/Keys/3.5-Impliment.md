# THE EDIT PROTOCOL (hard-won here — each rule cost a session)
1. **MEASURE BEFORE CHANGING.** Read the file:line. Never patch from a comment, a doc, or memory.
2. **GENERATE RATHER THAN RETYPE.** Copying 74 handler expressions by hand is how a mistyped rate-limit tier ships
   silently; extract and insert them by script, verbatim.
3. **NEVER let an edit's `old_text` end on a heading without re-emitting it** — that consumed a section heading **three
   times** in one session. Prefer `insert_line` for section work, and re-grep the headings afterwards.
4. **BYTE-SAFE I/O.** `[IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)` + `WriteAllText(…, UTF8Encoding($false))`.
   `Get-Content -Raw` decodes with the console codepage and corrupts every non-ASCII byte in the file.
5. **NO NON-ASCII LITERALS IN A SHELL STRING.** A single-quoted `'\u2014'` wrote six literal characters into a document;
   build such characters at run time (`[char]0x2014`).
6. **ONE BUILD PER COMMAND.** The shell caps at ~30s; a batch of builds times out and reads as a failure.
7. **POWERSHELL: a native command's stderr is a TERMINATING error.** Use `cmd /c "… 2>&1"`, or `2> file` then read it.
   Use `npm.cmd` (the `npm.ps1` shim is policy-blocked) and `-ExecutionPolicy Bypass -File` for `.ps1` scripts.
8. **NEVER report a repair without a DISK READ-BACK.** A repair verified only in memory was reported as done twice here
   and had never reached disk.
9. **Attribute pre-existing damage** (`git show HEAD:<file>`) before claiming you caused or cured it.
10. Secrets NEVER appear in a shell string, a command, or a git-tracked file.
11. **NEVER VERIFY A WRITE IN THE SAME BATCH AS THE WRITE.** Two commands issued together ran CONCURRENTLY and
    reported four of five files as still-old when all five were already correct — the write was fine and the CHECK was
    wrong. Sequence them in ONE command string, or in separate turns.
12. **A tool payload has a size cap** (~6000 chars): split a large edit into create-then-append rather than
truncating it.

# VERIFY (never assume success)

**For a Go change**, four targets, one command each, output to TEMP:
native · `GOOS=linux GOARCH=amd64` · `GOOS=js GOARCH=wasm` · `go build -tags console`. Prove **`Public/main.wasm`
untouched by size AND mtime**. Then `go test -count=1 .`: the expectation is **exactly ONE failure — the recorded
pre-existing AMM test (`TestCalculateBuyCost_WhaleSlippagePenalty`)**. Any other failure is a regression.

**For your change, run the gate that measures it:**
| Change | Gate |
| --- | --- |
| any `Public/**` module | `npm run verify:reachability` |
| markup / handler names / `data-*` controls | `npm run verify:handlers` |
| an overlay root or its open/close contract | `npm run verify:overlays` |
| a route in either entrypoint | `npm run verify:routes-parity` |
| a client fetch or a new API path | `npm run verify:api` (+ `verify:routes`) |
| an aspect, a row, or the index | `npm run verify:aspects` |
| SCSS | `npm run sass:build` (or `node node_modules/sass/sass.js` when the shim is blocked) |
| a duplicate-looking module | `npm run verify:duplicates` |

Also: **mojibake check** on every touched document (`U+00E2 == 0`), **`git status` = the intended set of paths**, and
`node --check` on each changed JS module (ESM: copy to `.mjs` if the checker objects).
