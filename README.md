## 📖 What this is

> **NFT-Seduction** is a social economic simulation built on **VirtualBabesTT**, a tactical card game, running on the
> **Voi** network and paying out through the **$VBV Faucet Vault**. You own characters, play them across a nine-tile
> board, and spend the rest of your time building the world around them: careers, clubs, territories, religions,
> businesses, companions and a household.

Three things make it unusual:

* **Your roster is alive.** AI citizens, children bots, companions and vehicles are *owned* entities you develop —
  each with its own stats, its own wallet and its own opinions about you.
* **Nothing is stored in a database.** The authoritative state is archived as compressed snapshots on the Voi
  blockchain, and the client keeps only a memo. The chain is the record.
* **Every micro-unit is accounted for.** An autonomous **Token-Sink Router** and **Reconciliation Kernel** track every
  micro-unit of **$VBV**, aiming at a ledger that always reconciles — no silent minting, no systemic drift.

**Status: Public Beta.** The first public version is being prepared for release. This README leads with what you can
do as a player; the engineering half begins at [For Developers](#-for-developers).

## Why You'll Love This Game

**You are not buying a deck. You are entering a world that remembers you.** Most card games end when the match does.
Here the match is one of eleven things you do — and what you do elsewhere changes what happens on the board.

* **The match is short; the consequences are not.** Win a board in minutes, then spend your time building the empire
  that decides the next one.
* **Your roster is alive.** AI citizens hold their own wallets, earn, spend, form households and develop opinions
  about you — and they keep acting while you are away.
* **The world notices what you do.** Rivals are real players, bounties are posted against real wallets, and the
  courthouse, the black market and the regional leaderboard move because of things people actually did.
* **Your rank cannot be bought.** Civil rank (**User → Manager → Governor**) is derived from what you hold, and a
  career path is chosen **once**.
* **You own what you build.** Art, entities and territory are yours to wear, sell and defend.

**In practice:** the player who shows up and builds will overtake the player with the better deck — that is the point
of the design, not a side effect of it.

## The core game — nine tiles

A match is played on a **nine-tile board**. Every card carries an **element** and a **mood**, and a match is decided
by the tiles you take, not by who owns the biggest deck:

* **Elements & moods** — nine tiles, each with its own affinity. *The element/mood interaction is ported from
  Triple Triad*, so a board you have seen before is a board you can already read.
* **The power stack** — a card's effective power is its own value **plus everything standing behind it**:
  **Coalition +10% · Regional +5% · household +1% per 60 stat points (cap +10%) · Wanted mitigated by Cunning
  (2 per point) · fatigue mitigated by Nurturing · +25 loyalty · a religious leader's blessing.**
* **SUDDEN DEATH** — a stalemate is broken by redistributing the board, not by a coin toss.
* **Formats** — Standard, **Bounty** (a target worth taking) and **Tournaments**.
* **Around your own match** — spectate live matches, replay any finished match frame by frame, and wager on results.

## What Gives This World Teeth

The eleven areas are how you get around. These are the systems that make the world worth paying attention to — and
most of them are easy to miss in your first hour.

* **A player-driven market, with an anti-whale rule.** The **entity market** lets you buy a stake in another player's
  entity: prices move on an AMM curve and dividends pay on performance. **No player may hold more than 25% of their own
  portfolio in a single entity**, so a whale cannot corner a market and freeze everyone else out.
* **The market is visible in the world.** A region's market vitality and its rumour coherence feed that region's
  world-dynamics signature, and the 3D world renders it — regions pulse with life and carry the aura of whoever owns
  them.
* **Auctions between players.** Real escrow, a **10% commission**, and settlement on the server — you are never
  trusting the other bidder.
* **You can borrow, with something at stake.** A loan is **collateralised against your cards**, so credit exists — and
  so does the risk.
* **Cyber warfare is a real layer.** A **Cyber-Audit** reads a rival club's treasury. A **Cyber-Lock** blocks a heist
  outright by encrypting the treasury's coordinates. A **sabotage protocol** breaks a security grid. A **cloak
  disruptor** flushes a hidden outlaw onto the bounty board.
* **Kidnapping is a trade, not a rumour.** A **kidnap gambit** takes a card — sometimes a Governor's favourite — and
  holds it for a **ransom** somebody has to pay.
* **The justice side answers back.** A justice power bonus against high-Wanted targets, **truth serum** to reveal what
  an opponent is carrying, a **reputation shield** to absorb a hit, and a bounty tax that feeds the **justice pool**
  funding the players who come for you.
* **Insurance, for when a card can scar.** Mutations mark cards, and **mutation insurance** guarantees the outcome —
  consuming the policy.
* **Governance is decided by votes**, and your voting weight comes from what you hold.
* **QuickPlay** — straight into a match from the main menu, when you do not want the full ceremony.
* **Play on a console and the crypto never comes near you.** Console play earns **Arena Vouchers** rather than tokens,
  and the console build ships with **no signing, no application calls and no chain rails at all**. The **voucher is your
  door into the PC version**: redeem it on a browser, link the account, and the same character carries on into the full
  world — with a path from virtual value into real `$VBV`. Buying from other players works there too: the trade happens
  behind your virtual balance, so the world behaves identically on both rails.

## Earn · own · brand

* **Earning** — matches and tournaments, bounty captures, contracts, the dividend yield from organisations you hold
  equity in, shops and creator sales. Everything is denominated in **$VBV**, in micro-units.
* **Owning** — a **bonded asset** is your own image, and you may wear it on anything you own: items, themes, bots,
  pets, vehicles, churches, clubs, shops and world content.
* **The one exception** — **cards can never be branded.** Deck cards, hand cards and religious-leader cards are
  excluded structurally, not by convention, so nobody can paint over the art you are playing against.
* **The art supply** — the game ships **117 placeholder frames**. Six are granted to every wallet free (the frames the
  app's own slideshows use); the rest are purchasable in-game.
* **Selling** — art you created can be listed and sold **player to player**, at your price, with the fee shown up front.
* **Your view** — you may also choose how *you* see the cards in front of you, using one of your own assets. That is a
  personal view only: no other player sees it and the match is never affected.

## A World Built From What You Do

The world is not scenery with a skin on it. It is a rendering of what everyone is doing — and it changes as they play.

### The 3D world reads the live simulation

* **Region height is vitality.** A region's raise is its **market vitality** (integer micro-units → a capped view
  height), scaled by the **power overlay** — the average entity power (0–600) derived from the companions and bots
  players developed there.
* **The aura is rivalry.** A contested region carries the **rivalry aura** of whoever is fighting over it, so the map
  shows where the pressure is.
* **Click a capital and it tells you why.** Warping into a region prints that region's world-dynamics signature, so the
  view explains itself instead of being decoration.
* **The arenas live there too.** Companion and vehicle contests are staged inside that world — transport runs and
  gang-up events with you and your bots.

### Ten signals, every one of them earned by players

**Market vitality · event dynamics · rumour coherence · citizen gravity · theme coherence · profile impact · faith
coherence · domestic coherence · economic perk · entity legitimacy** — combined into one score per region. Not one of
them is hand-set: each is derived from what players own, trade, build, believe, spread or contest.

### The weather is a projection of the market

A region's entity-market state resolves **deterministically** into a climate — **CALM · BREEZY · STORMY · BLIGHTED** —
plus a **disaster tier**. The same market state always produces the same weather, and it is served per region and shown
in the **Theme Dashboard** and on the Portfolio's *Market & Weather* screen.

### Events move the world

* **Seasonal events** run with their own status, join and reward flow, and a season history.
* **User events** can be created and entered by players themselves.
* **Entity events** are staged per region, training, rewarding or punishing the entities that take part.
* **Active events raise a region's `event_dynamics`** — run events in your region and the signature that every other
  system reads goes up. The world notices you holding a party.

### Tournaments

* A full **bracket** lifecycle with prize distribution, opened by a **verified on-chain buy-in** — the payment is
  checked against the chain, so a forged entry fails.
* **Entry closes when round 0 begins**: you cannot be inserted into a bracket that is already running.
* Finished tournaments are readable as history.

### World content you author

Players create **world content** — NPCs, animals, scenery and even **weather** — as ownable assets that others can buy
and that stand inside the regions. The world literally contains what its players built.

## Honest limits of the Beta

* **Public Beta.** Systems are landing continuously, so this README lags the code between releases.
* The **companion and vehicle arenas** are 3D-world placeholders today.
* **Snapshot archiving is off by default** right now, because the rail ships only once the complete save set is
  verified. Until then your state is kept locally.
* Two shops' tokens (**$NUGGET**, **$UNIT**) use **placeholder asset ids**, and a money door refuses to move real
  value while they are placeholders.
* The **Dev/Game Hub** catalogue is read-only — no purchase endpoint exists yet.

# 💠 Why This Game Is Worth Your Investment

*An honest case for spending your hours here — and your money, if you choose to.*

## The Investment You Are Making

Every game asks for your time. Very few are built so that time keeps paying you back after the session ends. Here,
what you put in goes into things that **persist, gain usefulness, and cannot be reset**:

| What you invest | What it becomes | Does it keep paying? |
| --- | --- | --- |
| **Hours in matches** | Levels, reputation, card progression | Yes — your level cap is what *unlocks* better careers |
| **One choice of path** | Justice, Criminal or Neutral — picked **once** | Yes — it fixes which shops, roles and rivals are yours |
| **Territory** | Districts, then a whole region | Yes — owned, never rented; a region is what makes a Governor |
| **Companions & vehicles** | A household with a six-axis power vector | Yes — that power lends back to every card you play |
| **AI citizens & children bots** | Entities that earn and develop opinions while you are away | Yes — the one asset class here that works while you sleep |
| **Art you create** | Bonded assets you can wear and sell | Yes — other players can buy what you made |
| **A stake in someone else's entity** | Shares bought on the **entity market** | Yes — dividends, and the anti-whale rule (**no more than 25% of your portfolio in one entity**) keeps any single holder from cornering a market |
| **Capital, if you want** | `$VBV` into upgrades, slots, land or art | Optional — nothing here *requires* spending to progress |

**None of that is a promise of profit.** It is a description of what the systems do with what you put in — and the
reason a player arriving today is not behind is that almost every rung here is **earned, not bought**.

## You Earn by Playing, Not Only by Paying

* **Matches and tournaments** — the bread and butter, paid in `$VBV`.
* **Bounties and contracts** — the justice and criminal ladders pay for actual work.
* **Dividends** — organisations you hold equity in pay a yield, and the Portfolio shows you exactly what.
* **The player market** — art you create sells to other players at your price, with the fee shown before you agree.
* **The creator economy** — publish into the world and earn royalties rather than tipping a platform.
* **Territory and religion** — the two structures designed to produce income over time rather than in one lump.

## Scarcity That Is Real

This is what turns a game into something worth defending: **the top of the ladder is finite by design**, so arriving
early and climbing properly is worth something.

* **A career path is chosen once.** No switching sides when the meta shifts.
* **A region has one Governor — and it takes *owning* a region to be one.** Not a fee, not an application.
* **Twenty-four religions exist.** A slot can be bought while slots remain; after that, only bought out.
* **Tier-4 career seats are seats** — Justice Commissioner, Underworld Boss and their peers.
* **Reputation ends at LEGENDARY, 1000.** The ladder has a top, and it is reachable — but it is not cheap.
* **Territory is owned.** There is one map, and its districts go to whoever takes them.

## Depth Is the Real Long-Term Asset

A game is only a good place to spend years if year two has more in it than year one. That is what the second layer is
for:

* **Eleven areas, 77 surfaces** — and you do not have to touch most of them to play well.
* **A living roster** — AI citizens with their own wallets, households and opinions, plus children bots being trained.
* **Institutions** — faith, churches, religions, clubs, alliances, governance, regions and a regional leaderboard.
* **A persistent economy** — markets with an AMM, lending, dividends, a black market and advertising.
* **A creator layer** — the art you make becomes part of everyone else's world.
* **A world you can look at** — regions in 3D with the entities that live there, and your household feeding your deck.
* **A real market, not a counter** — you can buy a stake in another player's entity, the AMM prices with slippage, and
  dividends pay on performance: the **entity market** is a large part of this economy, not a side feature.
* **An economy you can see** — each region's market vitality and rumour coherence feed its world-dynamics signature,
  and the 3D world renders the result: the economy is visible rather than buried in a table.
* **Financial surfaces with escrow** — player **auctions** settle server-side with a **10% commission**, and loans are
  **collateralised against your cards** rather than granted on trust.
* **Risk with consequences** — cyber-audits read a club's treasury, **Cyber-Locks** block heists outright, sabotage
  protocols break security grids, and **kidnap gambits** hold a card for a **ransom** someone has to pay.
* **A world people author, not just inhabit** — players create **world content** (NPCs, animals, scenery and even
  **weather**) that others can buy and that stands in the regions. The **weather itself is a deterministic projection of
  the market**: a region's entity-market state resolves to a climate — **CALM · BREEZY · STORMY · BLIGHTED** — and a
  disaster tier, served on its own route and visible on console too.

## Cross-Platform & Cross-Chain Parity

**Two rails, one world.** This is the hardest part of the architecture to copy, and it is not a "console mode" — it is a
segregation invariant, enforced by the build rather than by policy.

### Console: the crypto domain is segregated out

| Measured in the console entrypoint (`console_server.go`) | Count |
| --- | --- |
| Transaction-signing calls | **0** |
| Application-call construction | **0** |
| Raw-transaction submission | **0** |
| Chain-rail routes registered (`/api/v1`, `/api/bridge/onboard`, `/api/loans/take` · `repay`, `/api/faucet/claim`) | **0 of 5** |
| Public exposure | **none** — it binds loopback only, with no admin entry point |

A console player earns **Arena Vouchers**: a **non-crypto** representation of reward value, held as a declared liability
in the economy rather than as a wallet balance. The rule is written in the code itself:

> *"ArenaVouchers are non-crypto and must be converted to playerBalances via [redemption] … this function correctly does
> NOT directly access PlayerStats.ArenaVouchers."*

So the console side shares the **same economy, institutions and progression** as everyone else — with no key, no
signature and no chain call.

### The browser: the full economic layer

The web client holds `$VBV`, signs ARC-200 transactions, redeems vouchers, mints bonded assets, draws on the Faucet
Vault, routes every fee through the token-sink router, and archives the world's state as on-chain snapshots.

### The bridge, in both directions

```mermaid
flowchart TB
    C["Console player<br/>virtual balance only<br/>no keys, no signing"]
    B["PC / browser player<br/>holds $VBV, signs, mints"]
    V["playerBalances — the VIRTUAL LIABILITY LEDGER<br/>a trade between players moves $VBV inside it"]
    F["Faucet Vault — holds those balances<br/>and pays them out on a bridge"]
    CH["On-chain settlement — $VBV on Voi"]
    D["Console DLC store — USDC in, $VBV out to the creator<br/>NOT BUILT YET"]
    C --> V
    B --> V
    V --> F
    F -->|"bridge — voucher conversion or claim<br/>exit siphon · rollback if the chain leg fails"| CH
    C -.->|"the voucher is the door into the PC version"| B
    D -.-> F
```

**The mirror is exact, not approximate.** Every player holds a balance in the server's **virtual liability ledger**
(`playerBalances` — the code names it exactly that), and when one player buys from another the `$VBV` moves **between
virtual accounts inside that ledger** while the **physical vault balance is unchanged** (`auction_service.go:240`). A
console player sees a *virtual balance*; underneath it is the same economy as everyone else's, not a separate one.

**The Faucet Vault holds those balances and pays them out when you bridge.** On a bridge the vault dispatches the payout
from the ledger, applies an **exit siphon (2%)**, and — if the on-chain leg fails — **rolls the virtual balance back** to
the player rather than losing it.

**The voucher is the door into the PC version.** `HandleVoucherConversion` (`onboarding_service.go`, on the primary
server — the console build excludes it by ruling) converts non-crypto vouchers into the virtual ledger. That is what
lets a console account **carry on as a virtual account on PC**, play online in the same world, and push its value into
real `$VBV`.

**Console → economy** is therefore a redemption funnel: voucher, player id and platform go to the redemption gateway,
the entitlement is verified, the product is delivered, and the creator is paid through the market. **Economy → console**
is the direction whose contract type, **`ConsoleAssetReceipt`**, is *"a secure purchase or lease confirmation from an
external platform"* — and since **2026-10-08** it is a **live rail on the primary server**: the platform's fulfilment call
carries the receipt, the server asks the **platform's own API** for its record of the purchase, and the entitlement is
granted **idempotently**, keyed by the platform purchase id. It moves **no money** (the platform collected it), a caller
may name nothing but a purchase id, and it **refuses with its blockers** until a platform verifier is configured. The
bridge is reversible by design and non-custodial in practice: **no console device ever holds a key.**

### Why this is commercially decisive

Most Web3 games cannot ship on a console, because a shipped console application must not expose cryptographic rails or
private keys. This design does not work around that constraint — it **segregates the crypto domain to the browser and
mirrors the economy on the console**, so one world can be reviewed and shipped on a locked platform. That is a
distribution advantage, not a checkbox.

### The chain is a settlement rail, not a gameplay dependency

**Voi** is primary (AVM — where payouts and records complete); **Algorand** is inbound-compatible; a bridge router
carries other ecosystems; **Nautilus** handles token escrow. The authoritative state is **deterministic, replayable and
chain-agnostic**, which is what makes settlement layers interchangeable while the world stays correct.

**Not built yet, stated plainly:** the **console DLC store** is **designed and not built**. The intended model is that a
console player spends **virtual balance** (`$VBV`-equivalent) on DLC, shops and assets — with **instant payouts to the
seller or creator, exactly as on PC** — and that virtual balance is topped up by buying a **top-up with USDC, which lands
in the operator's admin wallet**. A top-up is a **sale, not a creation**: the vault transfers `$VBV` it already holds, so
a package the vault cannot cover is served as **unavailable with the shortfall named** rather than failing at checkout —
and if the vault cannot cover a **bridge**, the bridge reports itself **temporarily offline, awaiting maintenance**
instead of failing a player mid-sync.
Native console DLC payouts are a separate, slower, commission-heavy rail whose exact mechanics per platform are still
being researched, which is precisely why the app carries its own top-up path. When the store ships, its headroom is
**derived from the vault's own solvency** — a sale must fit inside what the vault holds *after* every virtual balance,
voucher, bounty, club treasury, dividend pool and committed payout — so the vault **cannot bounce a payout**.
`ConsoleAssetReceipt` **now has its writer** (2026-10-08): a platform purchase grants an entitlement idempotently, from
the platform's OWN record of that purchase, and the door **refuses with its named blockers** until platform credentials
are configured — the store itself remains unbuilt.

# 🔧 For Developers

*Everything from here down is the engineering half: how it is built, how it is verified, and where its state lives.*

## Architecture

| Concern | How it works |
| --- | --- |
| **Split WASM** | The **Go server is authoritative**; the **WASM client mirrors it**. Anything behind `//go:build !js && !wasm` never reaches the browser — which is exactly why a bare `go build` proves nothing here (see *Build targets*). |
| **Determinism** | Board state is hashed (big-endian, fixed width) and compared against the replay frame's state hash; a mismatch triggers recovery instead of a silent divergence. |
| **No database** | State is archived as gzip-compressed snapshots carried in **ARC-200 `$VBV` transaction notes** and reassembled from the Voi indexer. Local files exist for startup, diagnostics and runtime smoothness — **the chain is the record.** |
| **Ledger law** | `uint64` micro-units everywhere; **no floating point on any ledger, XP or economic path** (floats are display-only). Every fee routes through one token-sink door and every transaction reconciles. |
| **Secrets** | **ENV-ONLY.** Never served, never written to a tracked file. The network registry is redacted before every write, and an init assertion panics at boot if a secret-shaped key ever reaches the wire. |
| **AI** | **No cloud models.** AI citizens own their own wallets and run on local models. |
| **Console entrypoint** | A second server (`-tags console`) binds **loopback only** — a virtual mirror registering **0** signing calls, **0** application calls, **0** chain-rail routes and **no admin entry point**. The parity model is set out in [Cross-Platform & Cross-Chain Parity](#cross-platform--cross-chain-parity). |
| **Chains & escrow** | **Voi** is primary (AVM); **Algorand** is an inbound-compatible secondary; a bridge router is present for other ecosystems. Token escrow is handled by **Nautilus**, a third-party DeFi platform, rather than a bespoke custody contract. |

### How value flows

```text
        player action                        value flows                      sinks
   +-----------------------+        +-----------------------+      +--------------------+
   |  match . bounty       |        |  ONE token-sink       |      |  faucet            |
   |  contract . purchase  |------->|  router - every fee   |----->|  treasury          |
   |  lease . DLC          |        |  passes through here  |      |  approved system   |
   +-----------------------+        +-----------------------+      |  sinks             |
               |                               |                    +--------------------+
               v                               v
      uint64 micro-units             integer revenue split
      (never a float)                (shares reconcile)
                                              |
                                              v
                            reconciliation ASSERTED before any write
```

## 🚀 Development Setup

### Prerequisites
- Go 1.25.7+ (the toolchain floor is recorded in `go.mod`) 
- Node.js + npm (for SASS compilation)

### Quick Start
```bash
# 1. Clone and enter directory
git clone <your-fork-url> NFT-Seduction
cd NFT-Seduction

# 2. Install dependencies
npm install

# 3. Build everything (WASM + SASS + Server)
npm run build

# 4. Start the dev server (port 8090, isolated state)
npm run dev
# OR directly:
powershell -ExecutionPolicy Bypass -File tools/server/dev_server.ps1
```

The dev server:
- Runs on `http://localhost:8090`
- Uses isolated `./devdata/` directory (never touches production state)
- Uses public blockchain indexers (no local node required)
- Auto-opens browser to health check + client

### Build Targets
```bash
npm run build          # Full: clean → wasm:init → WASM → SASS → server binary → arch:scan
npm run wasm:build     # Compile Go → WebAssembly
npm run sass:build     # Compile SCSS → CSS
npm run server:build   # Compile Go server binary
npm run clean          # Remove all build artifacts
```

### Console Build (Loopback-only)
```bash
tools/build/build_console.sh    # Linux
tools/build/build_console.ps1   # Windows
```
Compiles with the `console` tag: it binds to `127.0.0.1` only (loopback), with **no admin entry point and no chain
rails** — a console can *see* its loans and its bridge history, but it cannot transact. It registers 268 routes today.

The other targets, all of which must stay green:

```bash
go build ./...                                     # native server
GOOS=linux GOARCH=amd64 go build ./...              # deployment target
GOOS=js GOARCH=wasm go build -o Public/main.wasm .  # the client
```

> **A bare `go build` is a false green here.** The architecture is split by build tags, so the browser target excludes
> every file marked `//go:build !js && !wasm`. Verify with the `linux/amd64` **and** the WASM builds — never one alone.

## Verification — the seven gates

Every gate reads the repository and **fails closed**; each carries a `--selftest` proving it *can* report a failure.
Run them before you trust a change:

```bash
npm run verify:aspects        # every numbered aspect of the index has a derived row
npm run verify:routes-parity  # the two entrypoints' route tables cannot drift apart
npm run verify:reachability   # every first-party module is reachable from a composition root
npm run verify:routes         # every routing-table name resolves; no orphan routes
npm run verify:duplicates     # one implementation per module basename
npm run verify:handlers       # every rendered control resolves to a published function
npm run verify:api            # no client path double-prefixes /api
```

And the browser-tier probes, which drive the real app rather than reading it:

```bash
npm run verify:entry          # loads the app headlessly and asserts the contracts
npm run verify:overlays       # every opener's target is VISIBLE (computed, not claimed)
npm run verify:portfolio      # every Portfolio screen renders real content, 0 page errors
npm run dev:test              # UI smoke test against a running dev server
```

**Why they exist.** `verify:reachability` was written after a metric that counted *references* was found to score
modules that render nothing; `verify:handlers` after 104 controls were found wired to functions nothing published.
A repository that measures itself is the only kind that stays honest.
